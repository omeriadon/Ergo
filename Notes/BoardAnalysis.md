# Board analysis (Deep Research)

- Deep Research (the canvas's ⋯ menu) hands the board to the server, which runs an agent over it in the background and writes what it finds as sync records. See `Plans/10-BoardAnalysis.md`. The app can be quit meanwhile. The toolbar's Analysis button only appears once there's a run to follow or results to open. Quick AI is the fast way to ask.
- While a run goes there's a Live Activity (`DeepResearchActivity`, with `DeepResearchAttributes` compiled into the widget too). The server can't update one, so it ends when the app next hears the run is over, from `BoardAnalysisStore.refresh`. The server's finish or failure alert is what reaches a closed app. Tapping the activity (`ergo://research/<board>`) or the bar above the tabs (`DeepResearchAccessory`, pinned to the foot of the sidebar in the wide layout) opens that board's analysis.
- `isKey` findings (2 or 3 a board) come first and stand out on the canvas. A finding's `objection` is a claim the person can add as a card (`AnalysisObjectionView`).
- Results come only from the replica: `BoardAnalysisStore` (`Ergo/Boards/`, in the environment from `ErgoApp`) reads `annotation` and `analysis` records on launch and after every sync, like `boardStore.shares`. No Defaults key. `accountChanged` forgets every one of them, since they belong to the account that had them, and the next pull brings back the new account's.
- What's shown is worked out each time, never stored: `BoardAnalysisShown` (ErgoProtocol) keeps the newest run's annotations that are still true of the board, and an edit makes the rest stale. Stale ones are hidden and the sheet says the board changed. A `running` status not heard from for `BoardAnalysisStatus.staleAfter` (since `started`, or its `heartbeat` when there is one) shows as interrupted.
- A source is annotated like a card: each finding cites an entry and quotes the source's words exactly, and `BoardAnalysisTools` refuses a quote that isn't in the text (`BoardQuote`: case, whitespace runs and curly quotes don't count). The app finds it again with `BoardQuote.range` to highlight it, so a finding can always be checked against its words.
- A long source is read in parts, all on the server and in one run, so nothing on the wire changes for it: `BoardAnalysisRequest.passes()` cuts each source with Break Down's `TextParts` at `partLimit`. The first pass is the board with each source's first part. Later ones are only the next parts, with fresh tools whose request holds just those parts, so their quotes are checked against the part the model read and cards and arrows can't be reported twice. The report limit is shared across passes, only the first pass's words become the discussion, and the server writes a `running` status with a new `heartbeat` before each later pass so a long run isn't shown as interrupted. A part's whitespace can differ from the source's, which `BoardQuote` ignores, so a part's quote is always found in the whole text.
- A text source's whole text is only read in the sheet (`AnalysisSourceText`, open when the sheet is about that source). Each quote is highlighted as an `ergo-finding:` link, and `AnalysisContent` scrolls to the finding instead of opening it. A finding whose quote can't be found there is listed without a highlight. A link source's page isn't kept on the device, so its findings are listed without highlights, and stay current while its title is unchanged. An edit that removes a text source's quote makes that finding stale, like a card's.
- Starting pushes pending sync changes, reads link sources' text on the device with `PageReader` (the CLI can't open links), then POSTs through `TranslationAccount.startAnalysis`. A link that can't be read is left out and the sheet says so. Viewers don't see Analyse but do see annotations.
- Hosted boxes get no environment, so the count badge goes through `CanvasBoxModel.annotationCount` and `CanvasSourceModel.annotationCount`, and `StatementBoxView`'s hand-written `==` compares it. An arrow's line follows its assessment through `CanvasBoardView.strengths`: solid, thicker for conclusive, dashed for weak, dotted for none, and green, orange or red with it.
- The board annotates itself. A conclusion's box is coloured by its support (`CanvasBoxModel.support`). A comment box (`BoardAnalysisShown.comments`) is the first finding's first sentence, drawn by the box's own SwiftUI outside its frame at the fixed `CanvasCommentLayout`, with a `UIControl` in the cell taking the taps, since SwiftUI can't receive them out there. Arrows with something to say get a `CanvasArrowNote` halfway along.
- `BoardSheet.boardAnalysis(board, focus:)` is `BoardAnalysisSheet`. Its markdown is `AskMarkdownView`, so links work as in Ask, and a library link goes to the Library through `NavigationManager`, which leaves the sheet waiting on the Board tab. Never call an intent's `perform()`.
- It never rules on whether a premise is true, and the sheet says so in its footer.
