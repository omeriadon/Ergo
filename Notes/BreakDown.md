# Break Down and translation

The original plan is `Plans/00-Translation.md`. `LogicEnglish` is in `Logic.md`.

- The app doesn't turn English into logic: logic is written by hand and read back as English. The server's translate route remains, and nothing uses its statement scope. Stages are `TranslationPipeline` stages in ErgoTranslation; never rename a stage's `name`.
- Break Down makes a board. It's opened from the Boards sheet's New Board menu, the wide sidebar's New Board menu (`BoardSheet.breakDown`, through the Board section's own sheet slot so creating or cancelling closes it), a source on the canvas (`BoardSheet.breakDownSource`) and the share sheet. The app streams `TranslationEvent`s over a WebSocket, through `TranslationAccount`, and doesn't use descriptors.
- Break Down carries on in the server like Ask does. `Defaults[.pendingBreakDown]` (`PendingBreakDown`, this device only) holds its request from the moment it's sent until it's created, cancelled, edited or fails, so a finished result survives a force quit too. `BreakDownSheet` follows it when it appears with the same input (`matches`, which prefers what the input came from over its text, since a shared page is read again), and `NavigationManager.resumeBreakDown` opens `BoardSheet.resumeBreakDown` at launch unless a restored sheet will do it. Anything new that talks to the server and takes a while follows this: a run the server owns and a way to find it again, never a socket the work depends on.
- `TranslationAccount.breakDown` runs the server's argument scope on pasted English: premises, a conclusion and claims, with no logic.
- A translation only returns logic that compiled and passed verify. Running out of tries gives no logic and an error, with the differences as issues. Verify's `structural` sends a wrong split of premises back to breakdown, since formalize must keep the premises it's given.
- A text over `EnglishValidator.characterLimit` goes through Break Down in parts (`TextParts`, `PendingBreakDown.parts`), on the paid plan. Each part is its own run, and `PendingBreakDown` moves on to the next as each finishes, so a closed app still finds it. Each part gets its own source and region.
