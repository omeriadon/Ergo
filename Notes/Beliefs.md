# Beliefs

- Beliefs is a page on the Library stack (`LibraryRoute.beliefs`, `SidebarItem.beliefs`), opened from the grid's Beliefs card or the wide sidebar's row, so both layouts show the same page. One belief is pushed as `LibraryRoute.belief(UUID)`. The route holds a plain `UUID` because `Library Enums.swift` is compiled into the widget too, which can't see `Belief`. See `Plans/16-Beliefs.md`.
- The question bank is `beliefQuestions.json` in ErgoCatalog (`Beliefs/`, Foundation only): ordered sets, each with a `#RRGGBB` colour of its own (`HexColor`, never `CategoryTheme`), a summary and questions. A question is a claim to rate, with up to 3 library entries. A set or question that can't be read is skipped, not the whole file. Ids are what answers are saved under: never change or remove one, and only add at the end.
- `BeliefQuestionTests` (in `ErgoAskTests`, since ErgoCatalog has no test target) checks the whole bank: unique ids, each question's id starting with its set's, a distinct valid colour per set, no statement ending in "?", and every entry in the library. Keep it passing as the bank grows.
- `BeliefScale` is 0 to 100 in steps of 10, with five words. Nil confidence is "No view".
- A `Belief` is the person's own or an answer to a question (`question` set). Answering a question makes its belief the first time and updates it after. `displayStatement` reads a question's words from the bank, so fixing a question's wording reaches existing answers.
- `changes` is every rating, the first included. From a set every answer is logged, even one that didn't move, so the history shows each time the set was taken. On a belief's own page only a move is logged, a second after the slider settles (or on leaving the page, if sooner), so dragging across values doesn't log each one. The wait re-checks afterwards, since No View can be tapped during it.
- `BeliefLedger` is in `Defaults.Keys.beliefs`, read and written with `@Default` like `practiceProgress`, and is in `TestDefaults.keys`.
- It syncs (`BeliefRecord`, `SyncController.recordBeliefs`, watched like bookmarks): a `belief` record per belief and a `beliefChange` record per rating, so ratings from two devices are both kept. Confidence isn't a field: it's the newest change's rating, so it always agrees with the history. A change's `date` is milliseconds, since ISO dates drop the fraction of a second and two changes in one second would lose their order.
- A question's belief id comes from the question's id (`Belief.id(answering:)`), so answering it on two devices before either syncs makes one belief. A belief deleted on one device and answered again later on another comes back: `recordBeliefs` sends `deleted` false only when it was rated after the tombstone, so a delete from elsewhere that hasn't been rebuilt yet still stands.
- A remote change rebuilds the whole ledger from the replica (`BeliefRecord.rebuild`), after recording local edits first so one the watcher hasn't reached isn't rebuilt away. What the replica can't read keeps its local value and is never deleted from here.
- The server only knows these kinds once it's built from this ErgoKit. Until then it refuses them (`SyncLimits`), which fails the whole push, so the server ships first.
- Taking a set is held in `@State` on `BeliefsView` (`BeliefSession`), like Practice's session. Each answer is saved as it's given, so leaving part way only loses the place, and the set picks up at its first unanswered question next time. "Start Again" in a set's context menu starts from the first question.
- Nothing is derived and stored: a set's progress and when it was last taken come from its questions' beliefs.
- There's no searching the bank. Beliefs aren't in `PersonalSearch` yet.
- The new-belief sheet is `LibrarySheet.newBelief`, with Cancel and Add in `.sheetDismissal` and `.sheetConfirmation`.
- Beliefs are personal (politics, religion), so they're never logged or sent anywhere.
